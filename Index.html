Text on a two-line LCD, from bare GPIO.

A 4-bit HD44780 driver in C for the LPC17xx, written at ISEL for the Electronics and Telecommunications degree. No vendor LCD library, just port registers and timed pulses.

Read the driver Source on GitHub

What it does

The driver initialises a 16x2 character LCD in 4-bit mode and exposes a small API: clear the screen, move the cursor, write a character, write a string. Everything runs on one GPIO port, and all timing comes from a microsecond delay library.

  • 4-bit interface, so only six GPIO lines are needed (four data, RS, E).
  • Standard HD44780 initialisation by instruction, with the datasheet delays.
  • R/W is tied to ground, so the driver never reads the busy flag and waits fixed times instead.

Wiring

The LCD is powered from a 5 V step-up, while the LPC17xx outputs 3.3 V logic. Contrast (VEE) comes from a resistor divider. Port 2 carries all six signals.

The driver

Each byte goes out as two nibbles, high first, with an enable pulse after each. The pulse is the heart of it:

static void write_4bit(unsigned char bits)
{
    LPC_GPIO2->FIOCLR = LCD_DATA_MASK;
    LPC_GPIO2->FIOSET = ((unsigned)(bits & 0xF)) << LCD_DATA_SHIFT;
    pulse_enable();
}

static void write_byte(unsigned char byte, int is_data)
{
    if (is_data) LPC_GPIO2->FIOSET = LCD_RS_MASK;
    else         LPC_GPIO2->FIOCLR = LCD_RS_MASK;
    write_4bit(byte >> 4);
    write_4bit(byte & 0xF);
}

Initialisation sends 0x3 three times, then 0x2 to switch to 4-bit mode, then the function set, display off, clear, entry mode and display on commands.

int main(void)
{
    DELAY_Init();
    LCD_INIT();
    LCD_LOCATE(0, 0);
    LCD_WRITE_STRING("TESTE LCD");
    while (1) { }
}

What went wrong first

The first version showed a uniformly dark top row and nothing else. That is how an HD44780 looks when it never receives its initialisation commands. The code was right. The mistake was in the pin map: header pins J2-40 and J2-41 are P0.10 and P0.11 on this board, not P2.0 and P2.1, so the enable line was never pulsed.

  • Check the board's pinout table before trusting the pin names in your own comments.
  • A dark top row with no text points at initialisation, not at contrast.
  • Keeping every signal on one port lets the driver use a single set of registers.
